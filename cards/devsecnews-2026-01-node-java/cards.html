Node.js 권한 경계 패치
Node.js 권한 경계 패치

한 줄 요약

이번 달은 권한 경계를 흔드는 이슈가 한꺼번에 공개됐습니다. 파일 경로와 로컬 소켓까지 같이 봅니다.

왜 위험

옵션만 믿으면 symlink/UDS 같은 우회 경로로 보안 경계가 깨집니다.

영향

허용 범위를 벗어난 파일 접근이나 내부 소켓 접근이 생깁니다.

오늘 조치

런타임을 보안 릴리스 버전으로 업데이트합니다.

[Source] https://nodejs.org/en/blog/vulnerability/december-2025-security-releases

Java 입력 경계(XML/템플릿/직렬화)
Java 입력 경계(XML/템플릿/직렬화)

한 줄 요약

입력이 XML 파서나 템플릿, 역직렬화로 들어가는 지점이 문제의 시작입니다. 이 경로를 먼저 정리합니다.

왜 위험

‘입력=코드’가 되는 경로에서 가젯 체인이나 XXE로 이어집니다.

영향

RCE나 정보 노출로 이어질 수 있습니다.

오늘 조치

외부 입력 기반 템플릿·직렬화 경로를 차단하거나 격리합니다.

[Source] https://skyve.org/blog/2026/1/12/security-advisory-cve-2025-10492-jaspersoft-library-deserialisation-vulnerability

DevSecNews 2026-01 — Node.js/Java 보안 요약(개발자용)
Struts S2-069(XXE)
Struts S2-069(XXE)

한 줄 요약

XML 파서 기본값이 남아 있으면, XXE 입력이 다시 처리됩니다. 파서 설정이 곧 방어선입니다.

왜 위험

외부 엔티티/DTD가 살아 있으면 외부 자원 접근이 열립니다.

영향

내부 자원 노출이나 SSRF 같은 파생 위험이 생깁니다.

오늘 조치

Struts를 패치 버전으로 올리고 XML 파서 보안 설정을 강제합니다.

[Source] https://cwiki.apache.org/confluence/display/WW/S2-069

개발자 도구(EOL 확장) 명령 주입
개발자 도구(EOL 확장) 명령 주입

한 줄 요약

개발자 도구 취약점은 서버보다 먼저 개발자 PC를 때립니다. EOL 확장은 패치가 없어서 제거가 빠릅니다.

왜 위험

레포/워크스페이스 입력이 확장 동작을 흔들어 로컬 실행으로 이어집니다.

영향

개발자 PC에서 임의 명령 실행로 번질 수 있습니다.

오늘 조치

조직 표준 확장 목록에서 해당 확장을 제거하고 워크스페이스 신뢰를 기본 거부로 둡니다.

[Source] https://spring.io/security/cve-2026-22718
체크리스트
DevSecNews 2026-01 — Node.js/Java 보안 요약(개발자용)
이번 달 개발자 체크리스트(10)
이번 달 개발자 체크리스트(10)
  1. Node.js permission model은 보안 경계로 쓰지 않고 realpath allowlist+OS 격리를 기본으로 둡니다.
  2. 파일 경로는 문자열 검증이 아니라 정규화+realpath 기준으로만 검증합니다.
  3. vm으로 유저 코드를 실행하지 않고 불가피하면 별도 프로세스/컨테이너로 격리합니다.
  4. UDS(로컬 소켓) 경로는 입력에서 직접 받지 않고 allowlist로 고정합니다.
  5. EOL 개발 도구/확장은 즉시 제거하고 조직 표준 allowlist로만 설치합니다.
  6. Node.js 런타임을 보안 릴리스 버전으로 업데이트합니다.
  7. fs.futimes() 사용 여부를 점검하고 보안 의미로 파일 타임스탬프를 신뢰하지 않도록 설계를 바꿉니다.
  8. Struts 사용 시 S2-069 패치 버전으로 업그레이드하고 XML 파서에서 DTD/외부 엔티티를 비활성화합니다.
  9. JasperReports 사용 시 외부 템플릿 업로드/로딩 경로를 차단하고 컴포넌트를 업데이트합니다.
  10. 워크스페이스 신뢰를 기본 거부로 두고 신뢰된 레포에서만 확장을 실행합니다.

이번 카드의 항목을 완료 처리합니다.
