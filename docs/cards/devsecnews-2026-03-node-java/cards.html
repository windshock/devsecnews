Trivy 공급망 공격: 보안 스캐너가 크리덴셜 스틸러로

Trivy Supply-Chain Attack: Security Scanner Turned Credential Stealer

SUMMARY

3월 19일, TeamPCP가 Trivy 스캐너를 장악해 CI/CD 파이프라인 수천 개에 크리덴셜 탈취 페이로드를 심었습니다.

GitHub Actions의 mutable tag를 악용한 태그 포이즈닝으로, 워크플로우 YAML을 변경하지 않고도 악성 코드가 실행됐습니다.

보안 스캐너 자체가 공격 벡터가 된 사건입니다. CI/CD 참조는 커밋 SHA로 고정하고, 영향 기간(3/19–22) 시크릿을 즉시 회전하세요.

SUMMARY

On March 19, TeamPCP compromised the Trivy scanner and planted credential-stealing payloads in thousands of CI/CD pipelines.

GitHub Advisory GHSA-h7xq-57qp-3kf2 describes how the plugin registry was hijacked. Within three days, Wiz Research, CrowdStrike, and Microsoft Defender independently confirmed the supply-chain breach.

RISK

A single compromised plugin registry bypassed all downstream integrity checks. Organizations running Trivy in CI trusted upstream packages implicitly.

IMPACT

CI/CD credential leak — GitHub tokens, AWS keys, and NPM tokens exfiltrated from build environments.

Action

Pin plugin hashes, enable Sigstore verification, and rotate all CI/CD secrets immediately.

WAF/IPS/IDS 탐지 공백: 파싱 불일치가 진짜 원인

WAF/IPS/IDS Detection Gaps: Parser Differentials Are the Real Cause

SUMMARY

시그니처 우회가 아니라 WAF–프록시–백엔드 간 파싱 불일치가 탐지 공백의 근본 원인입니다. WAFFLED 연구는 1,207개 고유 우회를 확인했습니다.

@JeppW의 Funky Chunks 연구, xclow3n의 Pingora request smuggling, nginx CRLF 엄격화 패치 논의를 함께 읽으면 이번 달 Netty HRS의 구조적 맥락이 보입니다.

검사 진입 조건, 검사 범위 정책, 정규화 순서, 파싱 기반 분석을 보강해야 합니다.

SUMMARY

Signature bypass isn’t the issue — parser differentials between WAF, proxy, and backend are the root cause of detection gaps. The WAFFLED study confirmed 1,207 unique bypasses, and projects like Funky-Chunks and Pingora-H1 reproduced real-world WAF evasion via HTTP parsing mismatches.

RISK

Security devices and backends parse HTTP differently — chunked encoding, header folding, and URI normalization each become bypass vectors.

IMPACT

Attackers craft requests that WAF sees as benign but backends interpret as malicious — SQLi, XSS, and path traversal slip through undetected.

Action

Run parser-differential tests (WAFFLED, Funky-Chunks) against your WAF+backend stack in CI.

CAPTCHA 우회 PoC: LLM 에이전트가 바꿔놓은 규칙

CAPTCHA Bypass PoC: LLM Agents Changed the Rules

SUMMARY

2025년 대규모 해킹으로 유출된 ID/PW를 활용한 크레덴셜 스터핑과 ‘내구제’ 명의도용이 급증했습니다. 대응으로 CAPTCHA 강화가 확산되고 있지만—

Playwright + Whisper + LLM 에이전트 조합으로 비용 $0, 100% 로컬에서 CAPTCHA가 자동 우회됩니다. DOM 난독화는 더 이상 유효한 방어가 아닙니다.

CAPTCHA 의존 전략 자체를 재검토해야 합니다. MFA·행동 기반 탐지·속도 제한을 병행하세요.

SUMMARY

Credential stuffing using leaked credentials from 2025 mega-breaches and ‘phone fraud’ identity theft surged. CAPTCHA was reinforced in response, but a PoC demonstrated LLM agents solving visual/audio CAPTCHAs in under 5 seconds with 85%+ accuracy — rendering them practically useless.

RISK

CAPTCHAs assume a gap between human and machine perception. Multimodal LLMs have closed that gap — CAPTCHA is now a speed bump, not a barrier.

IMPACT

Bot-driven credential stuffing at scale — account takeover, fraud, and identity theft accelerate beyond CAPTCHA’s ability to stop them.

Action

Layer behavioral analysis (device fingerprint + interaction pattern) on top of CAPTCHA, and enforce MFA for sensitive actions.

Lessons Learned

① 암묵적 경로를 신뢰한다

① Trusting Implicit Lookup Paths

PATTERN

Handlebars는 partial 이름을 prototype chain에서 찾고, Picomatch는 glob 결과를 권한 판단에 그대로 씁니다. node-forge는 malformed 입력을 사전 차단 없이 검증 함수에 넘깁니다.

ROOT CAUSE

"라이브러리가 알아서 걸러줄 것" — 편의를 위해 열어둔 fallback이 공격 경로가 됩니다.

PRINCIPLE

이름 조회에 hasOwn, glob에 정규화 경로 교차 검증, 서명에 형식 사전 검사를 기본값으로.

PATTERN

Handlebars resolves partial names via prototype chain. Picomatch feeds glob results directly into authorization decisions. node-forge passes malformed input to verification functions without pre-validation.

ROOT CAUSE

"The library will handle it" — convenience fallbacks left open become attack paths.

PRINCIPLE

Use hasOwn for name lookups, cross-validate normalized paths for globs, and add format pre-checks for signatures.

Action

obj[name] 대신 Object.hasOwn(obj, name) 검사를 추가합니다.

Action

Replace obj[name] with Object.hasOwn(obj, name) checks.

Lessons Learned

② 관리 경로와 비즈니스 경로가 섞여 있다

② Admin and Business Paths Are Mixed

PATTERN

Actuator health group 경로 아래에 비즈니스 엔드포인트가 배치되면 permitAll() 정책이 그대로 상속됩니다. CloudFoundry Actuator도 같은 패턴입니다.

ROOT CAUSE

URI prefix를 공유하는 순간 접근 제어가 의도치 않게 상속됩니다.

PRINCIPLE

관리 경로는 /internal/mgmt 등 전용 prefix로 분리하고, 비즈니스는 /api/** 에만 배치하세요.

PATTERN

When business endpoints sit under Actuator health group paths, permitAll() policies are inherited unintentionally. CloudFoundry Actuator follows the same pattern.

ROOT CAUSE

The moment you share a URI prefix, access controls are inherited unintentionally.

PRINCIPLE

Isolate admin paths under /internal/mgmt with dedicated prefixes. Deploy business logic only under /api/**.

Action

Actuator 경로 아래 비즈니스 엔드포인트를 즉시 제거합니다.

Action

Remove business endpoints from under Actuator paths immediately.

Lessons Learned

③ 프록시와 백엔드가 같은 규칙을 보지 않는다

③ Proxy and Backend Don’t Share the Same Rules

PATTERN

Netty는 chunked extension의 quoted string을 다르게 파싱해 요청 경계가 어긋나고, ZooKeeper는 reverse DNS를 호스트 검증에 사용해 SAN과 불일치합니다.

ROOT CAUSE

두 컴포넌트가 같은 입력을 다른 규칙으로 해석하면 경계가 무너집니다. WAFFLED 1,207개 우회도 같은 뿌리.

PRINCIPLE

보안 업데이트에 프록시-백엔드 파서 일치 테스트를 묶고, 호스트 검증은 SAN 직접 비교로.

PATTERN

Netty parses chunked extension quoted strings differently, causing request boundary misalignment. ZooKeeper uses reverse DNS for host verification, creating SAN mismatches.

ROOT CAUSE

When two components parse the same input with different rules, boundaries collapse. The WAFFLED 1,207 bypasses share the same root cause.

PRINCIPLE

Bundle proxy-backend parser alignment tests into security updates. Use direct SAN comparison for host verification.

Action

프록시-백엔드 요청 경계 일치 테스트를 CI에 추가합니다.

Action

Add proxy-backend request boundary alignment tests to CI.
