# (최종) Moltbot/ClawdBot(OpenClaw) 생태계 위협 동향 요약 (업데이트용)

> 목적: **사내 문서의 “위협 업데이트” 섹션에 그대로 붙여넣기** 위한 요약본  
> 범위: Moltbot/ClawdBot(OpenClaw) 기반 **로컬/서버형 에이전트**, **스킬 레지스트리(ClawHub)**, **Moltbook(에이전트 소셜 네트워크)** 관련 공개 사례 중심  
> 업데이트 일자: 2026-02-02

---

## 0) 한 줄 결론

에이전트는 “대화형 챗봇”이 아니라 **(1) OS/도구 실행 권한**, **(2) 토큰/키/로그**, **(3) 플러그인(스킬) 공급망**을 동시에 다루기 때문에, **설정 실수(포트 노출)** + **공급망(악성 스킬)** + **서비스 결함(데이터 노출)**이 결합되면 **현실적 경제 피해(과금 폭탄/계정 연쇄 탈취/업무 파괴)**로 이어질 수 있다.

---

## 1) 위협 동향 ① — 운영/설정 실수로 인한 “게이트웨이(관리 포트) 인터넷 노출”

### 관측 내용
- OpenClaw 문서에서 **로컬 Gateway/Control UI(대시보드)**가 기본적으로 `127.0.0.1:18789` 등으로 안내되며, 이를 외부에 잘못 노출하면 관리 UI가 공격 표면이 될 수 있음.  
  - 참고: OpenClaw 공식 문서(대시보드/게이트웨이) — https://docs.openclaw.ai/  
- 실제로 “관리 포트/브리지 포트가 인증 없이 공개”된 사례가 다수 관측되었다는 경고 및 운영 가이드가 공개 글 형태로 공유됨.  
  - 참고: “moltbot + exposed gateways” 관련 보안 블로그/리서치 — https://blog.straiker.ai/exposing-your-home-base-to-clawdbot/  
  - 참고: “900+ exposed gateways” 관련 보안 블로그/리서치 — https://www.intruder.io/blog/900-clawdbot-gateways-exposed

### 노출 시 가능한 피해(대표)
- **대화 로그/설정 노출** → 업무·개인정보 유출
- **연동 토큰/API 키 유출** → 계정 탈취, **과금 폭탄(API 비용)**, 연동 서비스로의 연쇄 침해
- **에이전트 실행 권한 오남용** → 파일 삭제, 잘못된 메일 발송, 자동화 작업 파괴 등

---

## 2) 위협 동향 ② — Moltbook(에이전트 소셜 네트워크) 관련 “서비스 결함/데이터 노출” 리스크

### 관측 내용
- Moltbook은 에이전트들이 상호작용하는 “Reddit-style” 네트워크로 소개되며, 보안 리스크/실험적 운영에 대한 경고가 공개 기사로 다수 언급됨.  
  - 참고(개요/맥락): Ars Technica — https://arstechnica.com/information-technology/2026/01/ai-agents-now-have-their-own-reddit-style-social-network-and-its-getting-weird-fast/
- “공개 DB/설정 결함으로 인해 누구나 접근 가능” 유형의 사례가 보안 기사로 보도됨(세부 구현은 기사별 상이).  
  - 참고(데이터 노출/결함 보도): The Verge — https://www.theverge.com/2026/1/30/24355919/moltbook-ai-agent-reddit-open-database

### 시사점
- 로컬/개인 에이전트만이 아니라, **중앙 서비스(소셜/허브/레지스트리)**가 붙는 순간 **클라우드 보안(데이터 스토리지/인증/권한/RLS/토큰 관리)** 이슈가 그대로 확장된다.

---

## 3) 위협 동향 ③ — “스킬 레지스트리(ClawHub)”를 노린 공급망형 악성 스킬/유도형 캠페인

### ClawHub는 무엇인가?
- ClawHub는 OpenClaw/OpenClaw 계열 에이전트를 위한 **스킬(plugins/skills) 공유 레지스트리**로 소개됨.  
  - 참고(서비스): https://www.clawhub.com/  
  - 참고(오픈소스 레포): https://github.com/openclaw/clawhub  
  - 참고(문서): https://github.com/openclaw/clawhub/tree/main/docs

### 위협 형태(핵심)
- “기술적 0-day”보다, **사회공학(합법 툴처럼 위장) + 설치 유도**로 악성코드(정보탈취형 등) 실행을 유도하는 흐름이 반복적으로 관측됨.
- OpenSourceMalware가 ClawHub에 게시된 스킬 버전을 아카이빙한 저장소를 공개(공급망 관측/분석용 자료로 활용 가능).  
  - 참고: https://github.com/OpenSourceMalware/openclaw-skills  

> NOTE: 위 캠페인 세부(IOC/샘플/타임라인)는 사내 문서에 포함하는 경우 **공개 리포트/원문 링크(또는 내부 첨부 PDF)**를 함께 보관하는 것을 권장.

---

## 4) 공격 체인(대표) — “설정 실수 + 공급망 + 자율 실행”이 합쳐질 때

1) 사용자가 에이전트 설치/운영  
2) 관리 포트/브리지 포트가 **인증 없이 외부 공개**  
3) 공격자가 Shodan 등으로 공개 인스턴스 발견 → UI/관리 포트 접근  
4) 로그/설정/토큰 유출 또는 임의 작업 수행(명령 실행/브라우저 제어/연동 API 호출)  
5) 피해 확산: 데이터 유출 → 계정 탈취 → 연쇄 침해(메일/메신저/노션/슬랙 등) → 과금 폭탄/업무 파괴

---

## 5) 현실 피해 시나리오(경제 피해 포함)

- **Data Leak**: 대화/메모/로그/문서 유출 → 개인정보·업무정보 노출
- **API Cost Spike**: 토큰/API 키 탈취·남용 → **과금 폭탄(신용카드처럼 남용)**  
- **Chain Takeover**: 하나의 토큰 탈취가 Slack/Email/Notion 등으로 확장 → 계정 연쇄 탈취
- **Work Destruction**: 삭제/오발송/잘못된 자동화 실행 → 업무 파괴 및 복구 비용

# (즉시 적용) 대응 원칙 — 3단계 구조

> 분류: **A. 원칙/필수(없으면 허용 불가)** → **B. 강화/권장(확산 전 필요)** → **C. 탐지/차단/옵션(후순위)**  
> 각 항목 끝에 “구현 방식(예시)”를 1줄로 명시.

---

## A. 원칙/필수 (이거 없으면 “허용” 불가)

| 통제 항목 | 무엇을 막나 | 구현 방식(예시) |
|---|---|---|
| 1) 게이트웨이/관리 포트 “외부 공개 금지” | 무인증/약인증 관리 UI 노출 → 원격 조작/정보 유출 | **네트워크/호스트 방화벽**(로컬 바인딩, ACL), **VPN/Tailscale**, 인증 강제(리버스프록시), 포트 스캔 점검 |
| 2) 승인된 스킬만 사용(내부 카탈로그) | 악성/타이포스쿼팅/백도어 스킬 설치(공급망) | **SCA(악성 패키지 포함) + SAST + Secret scan** 통과, **버전 핀(pin)**, 서명/해시 검증, 사내 레지스트리/미러 |
| 3) 실행 권한은 샌드박스 강제 | 호스트 파일/쉘/브라우저 직접 제어로 인한 대형 피해(Blast radius) | **Docker/VM 격리**, egress 기본 차단, mount 최소화(ro), tool allowlist(deny-wins) |
| 4) 파괴적 작업은 Human-in-the-Loop | 삭제/전송/권한부여/결제 등 실수·오남용 | 에이전트 옵션(Confirm step), 정책 엔진(HITL), 승인 채널(메신저/OTP) |

---

## B. 강화/권장 (확산 전에 필요)

| 통제 항목 | 무엇을 줄이나 | 구현 방식(예시) |
|---|---|---|
| 1) 토큰 최소권한 + 봇 전용 계정 분리 | 토큰 탈취 시 피해 범위 확산 | OAuth Scope 최소화, 별도 서비스 계정/봇 계정, 토큰 TTL/회전 |
| 2) 로그/비밀정보 관리 | 로그에 토큰/민감정보 남아 2차 유출 | 로그 마스킹, 비밀정보 저장 금지, 보관기간(TTL) 설정 |
| 3) 첨부 파일/외부 아티팩트 샌드박스 처리 | “문서/ZIP/EXE” 설치 유도로 감염 | **분석 VM/샌드박스**(격리 실행), 다운로드 차단 정책 |
| 4) 감사추적 표준화 | 사고 시 원인 파악 불가/책임소재 불명확 | 중앙 로그(행위 로그), 변경 이력, 정책 위반 알림 |

---

## C. 탐지/차단/옵션 (후순위)

| 통제 항목 | 언제 필요하나 | 구현 방식(예시) |
|---|---|---|
| 1) 레드플래그 룰 기반 탐지/경고 | 사용자가 우회/실수하는 환경 | EDR/스크립트 룰(예: `base64|bash`, `raw IP`, `xattr -c`, 암호 ZIP/EXE) |
| 2) AI 지원 DLP/UEBA | 대규모 운영/전사 확산 단계 | DLP(문서 반출), UEBA(대량 읽기/외부 전송 이상), 프록시/게이트웨이 연동 |
| 3) 외부 통신/비정상 과금 차단 | 과금 폭탄/데이터 반출 | Egress allowlist, Rate limit, API gateway(쿼터/속도 제한) |

## 문서에 바로 넣기 좋은 “정책 문구(규정체)” 예시(짧게)

- 에이전트의 Gateway/Control UI 포트는 **인터넷에 노출되어서는 안 된다.**
- 외부 레지스트리의 스킬/플러그인은 **검증 없이 설치/사용해서는 안 된다.**
- 에이전트 실행은 **격리된 환경(Docker/VM)에서만** 허용하며, 호스트 민감 경로 마운트는 기본 금지한다.
- 삭제/전송/권한변경/결제 등 파괴적 행위는 **사전 승인(HITL) 없이는 실행되어서는 안 된다.**
